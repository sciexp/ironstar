# Migrate ironstar from crane to crate2nix — implementation plan

> For agentic workers: implement this plan task-by-task against the existing jj diamond development join.

**Goal:** Replace ironstar's crane-based Rust build substrate with crate2nix's committed `Cargo.nix` and per-crate `buildRustCrate` derivations to gain per-dependency-crate nix cache granularity.

**Architecture:** A committed `Cargo.nix` (no IFD) drives one `buildRustCrate` derivation per crate, consumed in `modules/rust.nix` with the pinned 1.94.1 toolchain threaded into `buildRustCrateForPkgs`.
Two parent-reaching members (`ironstar`, `ironstar-analytics-infra`) get a `combinedSrc`-derived per-member `src` override that re-establishes the `../../` asset layout; the other nine use the generated subdir src.
The migration is additive through task 5 (`-c2n` packages coexist with crane) and removes crane only at the end.

**Tech stack:** nix flakes, flake-parts, crate2nix, rust-overlay (1.94.1), buildRustCrate, cargo nextest, cargo clippy, GitHub Actions, buildbot-nix.

## Isolation and integration

Apply executes via the existing jj diamond development join in a single working copy, on the `ironstar-8g3-crate2nix-migration` chain; commits are orchestrator-routed onto that chain.
jj mode is in force (`.jj/` present), so no git worktrees are created and `isolation: "worktree"` is never set.
Integration is user-gated: the substrate swap (task 5) is held for an explicit human go/no-go informed by the eval-time and cache measurements, and no autonomous PR is opened.
The reference design lives in `design.md`; the durable requirements live in `specs/rust-build-substrate/spec.md`; the task ledger lives in `tasks.md`.

## Task 1: bootstrap crate2nix input and committed Cargo.nix

- [ ] **Step 1:** Add `crate2nix.url = "github:nix-community/crate2nix"` and `crate2nix.inputs.nixpkgs.follows = "nixpkgs"` to the inputs block in `flake.nix`; do not add `nixConfig.allow-import-from-derivation`.
- [ ] **Step 2:** Add a `regenerate-cargo-nix` recipe to the justfile running `nix run github:nix-community/crate2nix -- generate` at the repo root.
- [ ] **Step 3:** Run `just regenerate-cargo-nix` and commit `./Cargo.nix`; confirm no `crate-hashes.json` is emitted.
- [ ] **Step 4:** Inspect the generated `Cargo.nix` and confirm all 11 local members appear, each with `src = ./crates/<name>` (the per-member keystone).
- [ ] **Step 5:** Verify `nix flake metadata | rg crate2nix`, `nix eval .#packages.aarch64-darwin --apply builtins.attrNames`, and that `rg -c '^\[\[package\]\]' Cargo.lock` reconciles with the distinct `crateName/version` pairs in `Cargo.nix`.
- [ ] **Step 6:** Record the `nix eval .#packages.<sys>.ironstar-c2n` eval time and crane's current eval time as the ≤2x baseline.
- [ ] **Commit:** input plus committed `Cargo.nix` plus regeneration recipe.

## Task 2: crate overrides, parallel packages, and source injection

- [ ] **Step 1:** Add `ironstarCrateOverrides` in `modules/rust.nix`: `libduckdb-sys` (cc, `HOME=/tmp`), `aws-lc-sys` (cmake, perl — mandatory), `ring` (perl); rely on the nixpkgs default for `libsqlite3-sys`; add no global pkg-config; drop the Linux openssl buildInput provisionally.
- [ ] **Step 2:** Import `./Cargo.nix` with `buildRustCrateForPkgs` overriding `rustc`/`cargo` to the pinned `rustToolchain` and merging the overrides onto `defaultCrateOverrides`.
- [ ] **Step 3:** Define `ironstar-c2n` (`workspaceMembers."ironstar".build` with `release = false`) and `ironstar-release-c2n` (`release = true`).
- [ ] **Step 4:** Build per-member derived srcs (fixed `name`s) for `ironstar` and `ironstar-analytics-infra` that re-materialize `static/dist` and `assets/ducklake-catalogs` two levels above the crate root, and set them via the `src` override.
- [ ] **Step 5:** Add `ironstar-c2n`/`ironstar-release-c2n` to the package-set-invariant `excluded` list.
- [ ] **Step 6:** Build `nix build .#ironstar-c2n .#ironstar-release-c2n` on aarch64-darwin and x86_64-linux; run `result/bin/ironstar --help`.
- [ ] **Step 7:** Assert the embedded `AssetManifest` and the embedded catalog are NON-EMPTY (smoke run or dedicated assertion) and that migrations resolve; re-measure eval time against the ≤2x gate.
- [ ] **Commit:** overrides, parallel packages, and the two source overrides.

## Task 3: migrate the test and clippy gate off crane

- [ ] **Step 1:** Re-implement `workspace-test` as a crane-free derivation over `combinedSrc` running `cargo nextest run --workspace --no-tests=pass` (default profile) with the pinned toolchain, native deps (cc/cmake/perl/sqlite, pkg-config), and `HOME=/tmp`.
- [ ] **Step 2:** Re-implement `workspace-clippy` likewise running `cargo clippy --workspace --all-targets -- -D warnings`.
- [ ] **Step 3:** Delete the 20 per-crate `*-test`/`*-clippy` packages generated by `genAttrs` over `libCrates`.
- [ ] **Step 4:** Build `nix build .#checks.<sys>.workspace-test .#checks.<sys>.workspace-clippy`; compare the test count to the 911-test baseline.
- [ ] **Step 5:** Verify `nix eval .#checks.<sys> --apply builtins.attrNames` still shows 14 names and `nix eval .#packages.<sys> --apply builtins.attrNames` shows the 20 per-crate attrs gone.
- [ ] **Step 6:** If dependency-recompile cost is unacceptable, fall back to one retained crane `buildDepsOnly` feeding only these two derivations and surface the decision to the maintainer.
- [ ] **Commit:** crane-free gate and per-crate package deletions.
